# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33–37) | **Timezone handling, instant truncation, and overnight shifts ignored.** `punch_in` can be in UTC or tz-naive. Calling `.replace(hour=h, minute=m)` directly on a UTC or arbitrary datetime without converting to IST compares mismatched clocks. Also, R1 requires truncating instants to whole seconds before calculations, and overnight shifts require determining the shift's base date accurately. | Punch-in at `04:05:00 UTC` (`09:35 IST`) is compared with `hour=9` on UTC time, resulting in a large negative or incorrect diff. | Converted `punch_in` to IST, truncated microseconds to whole seconds, identified the correct shift base date and start time, and computed elapsed seconds from shift start. |
| 2 | `compute_late_minutes` (lines 36–37) | **Grace period boundary logic error (R2).** Evaluates `minutes = int(seconds / 60)` then `minutes if minutes > 10 else 0`. If punch-in is `09:40:01` for a `09:30:00` shift, `seconds = 601`, `int(601/60) = 10`, so `10 > 10` evaluates to `False`, returning `0` instead of `10`. R2 specifies: 09:40:00 -> 0; 09:40:01 -> 10. | Punch-in at `09:40:01` for shift `09:30` returns `0` instead of `10`. | Evaluated elapsed seconds strictly: late only if `elapsed_seconds > 600` (strictly > 10 minutes), then returning `int(elapsed_seconds // 60)` from `shift_start`. |
| 3 | `compute_work_hours` (lines 40–41) | **Python `round()` uses banker's rounding (round half to even) instead of half-up (R4, R8).** Built-in `round(2.125, 2)` gives `2.12` rather than `2.13`. | Durations with mid-point halves (e.g. 2.125 hours) round down to 2.12 instead of half-up to 2.13. | Implemented half-up rounding using `decimal.Decimal(str(val)).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)`. |
| 4 | `compute_overtime` (lines 44–47) | **Missing 30-minute threshold (R3) and timezone/overnight shift handling.** Uses `max(0, ...)` without checking the $\ge 30$ minutes minimum condition. Also, assumes `end` is on `date_str` without accounting for overnight shifts where `shift_end <= shift_start` ends on the next calendar day. | Punch-out 10 minutes past shift end returns `10` instead of `0`. An overnight shift (e.g. 22:00 to 06:00) yields a huge negative number because `end` was placed on the starting calendar day. | Calculated shift end in IST (adding 1 day if `shift_end <= shift_start`), computed total minutes past shift end, and returned `floor(minutes)` only if $\ge 30$, otherwise `0`. |
| 5 | `/health` (lines 72–74) | **Readiness probe does not ping MongoDB.** Always returns `{"status": "ok"}` even when the database is unavailable, violating the contract (200 only if MongoDB answers a ping, otherwise 503). | Disconnecting MongoDB still causes `/health` to return 200 OK. | Added `client.admin.command("ping")` inside a `try/except` block, returning `503` when unreachable. |
| 6 | `POST /employees` (lines 53–60, 78–85) | **Missing validation for `shift_start == shift_end`, email, and `emp_code` regex.** OpenAPI requires 422 for `shift_start == shift_end`, invalid email pattern, or non-conforming `emp_code`. | Sending `shift_start: "09:00", shift_end: "09:00"` or invalid email succeeds with 201 instead of 422. | Added Pydantic field validators and regex patterns matching `openapi.yaml`, checking that `shift_start != shift_end`. |
| 7 | `POST /employees` (lines 81–85) | **Concurrency race condition on `emp_code` and date format bug.** Relies on `find_one()` before `insert_one()` without a database-level unique index on `emp_code`, allowing duplicate employees under concurrent requests. Also stores naive `datetime.now()` instead of BSON UTC datetime and returns doc without converting `created_at` to epoch milliseconds. | Concurrent identical creation requests both create records. Response returns `created_at` as ISO string or datetime rather than epoch milliseconds. | Created unique index on `emp_code`, handled `DuplicateKeyError` by raising 409, and serialized `created_at` as epoch milliseconds. |
| 8 | `GET /employees` (lines 88–96) | **Incorrect pagination offset and total count.** Computes `skip = page * page_size`, skipping the first 20 records on page 1 (page 1 starts at index 20 instead of 0). Also `total = count_documents({})` counts the entire collection ignoring the `department` filter (violates R10). | `GET /employees?page=1&department=Sales` returns items 21-40, and returns the total employee count across all departments. | Changed offset to `(page - 1) * page_size`, updated `total = db.employees.count_documents(q)`, added sorting by `emp_code: 1`, and enforced `page >= 1, 1 <= page_size <= 100`. |
| 9 | `POST /attendance/punch-in` (lines 99–121) | **Check-then-insert race condition on attendance records.** Checks `find_one({"emp_code": ..., "date": ...})` then inserts. Under concurrent punch-ins for the same employee and date, both succeed or corrupt data, violating the strict concurrency contract (exactly one 201, rest 409). | Simultaneous identical punch-in requests both succeed with 201. | Created a unique compound index on `("emp_code", "date")` at startup, catching `DuplicateKeyError` to return HTTP 409. |
| 10 | `POST /attendance/punch-in` (lines 100–105) | **Missing employee existence check (causes 500 error).** If `emp_code` does not exist, `emp` is `None`, so `emp["shift_start"]` raises `TypeError: 'NoneType' object is not subscriptable` returning 500 instead of 404. | Sending a punch-in for a non-existent employee returns 500 instead of 404. | Added `if not emp: raise HTTPException(404, "Employee not found")`. |
| 11 | `POST /attendance/punch-in` (lines 102–103) | **Wrong attendance date determination for overnight shifts (R1).** Calculates `d = ts.date().isoformat()` using server local time without IST timezone awareness or overnight shift logic. For overnight shifts (e.g. 22:00-06:00), punch-ins before `shift_end` belong to the previous calendar day's shift date. | Punch-in at 01:00 AM IST for an overnight shift is recorded under the current date instead of the shift's starting date. | Implemented R1 attendance date resolution: convert instant to IST, determine if it falls within the prior day's overnight shift, and record the correct IST attendance date. |
| 12 | `POST /attendance/punch-in` (lines 63–67, 102) | **Timestamp validation, truncation, and status constraints.** `punched_at` was unconstrained, accepting seconds-looking integers (e.g. 1700000000), floats, or out-of-range values, which must return 422. It also permitted statuses like `ABSENT` or `LEAVE` which cannot be punched in. | Sending `punched_at: 1700000000` or `status: "LEAVE"` succeeds with 201 instead of 422. | Enforced `EpochMillis` range `[100000000000, 4102444800000]`, restricted status to `["PRESENT", "WFH", "ON_DUTY"]`, and truncated timestamps to whole seconds (R1). |
| 13 | `GET /attendance` (lines 144–150) | **In-memory sorting and full collection loading into RAM.** Executes `list(db.attendance_logs.find(q))` and sorts in Python. Fails under 100k records, causing OOM or high latency. | Requesting `/attendance` with 100k records in MongoDB causes large memory spike and timeout (> 10s). | Replaced in-memory sorting and pagination with MongoDB native `.sort([("date", -1), ("emp_code", 1)]).skip(...).limit(...)` backed by compound indexes. |
| 14 | `GET /attendance` (lines 136–142, 145) | **Missing `date_from > date_to` validation and secondary sort.** Does not validate date order (OpenAPI requires 422 when `date_from > date_to`). Also only sorted by `date` descending, missing the contract-mandated secondary sort by `emp_code` ascending. | Calling `/attendance?date_from=2026-07-10&date_to=2026-07-01` returns 200 with empty list instead of 422. | Added validation raising 422 if `date_from > date_to`, and sorted by `[("date", -1), ("emp_code", 1)]`. |
| 15 | Both `/attendance` endpoints | **Contract schema mismatch on `id` and datetime types.** Returns MongoDB ObjectId string as `"id"`. The `AttendanceRecord` schema explicitly specifies no `id` field, and requires `punch_in`/`punch_out` as integer epoch milliseconds (or `null`), not BSON datetimes or ISO strings. | Response contains unexpected `"id"` key, and datetimes are not serialized as integer epoch milliseconds. | Stripped `_id` / `id` from the response, and serialized all instant fields to integer epoch milliseconds conforming to `AttendanceRecord`. |

Also note anything you looked at and decided was **not** a defect, and why:
- **`IST = timezone(timedelta(hours=5, minutes=30))`**: The timezone definition itself is correct for Indian Standard Time (UTC+05:30), but it was not being utilized correctly across punch timestamps and boundary calculations.
- **`status` defaults to `"PRESENT"` in punch-in**: This matches the contract specification (`default: PRESENT`).
- **Absence of `ABSENT` / `LEAVE` creation endpoint**: Looked at whether an endpoint should create `ABSENT` or `LEAVE` records; the specification explicitly confirms that no endpoint creates them—they are seeded or created via manual regularization (`PATCH`).
- **Audit trail `history` starting as empty list `[]`**: Confirmed that punch-in and punch-out should never write to `history`, and new records must start with `history: []`.
